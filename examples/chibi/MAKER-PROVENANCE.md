# 赤壁 · 制作侧追溯与成对连续性门槛

本页给继续制作的人使用，不进入正文界面。图片和历史提示词均未修改，没有重生成，也没有最终创作者批准。

## 先分清三种材料

1. **真实逐图请求**：[原始记录](../../samples/reader/narrative-v1/prompts.json)。`images[i].prompt` 是初版请求，不能因为父层 `file` 已更新为 v2，就把它误认成 v2 的实际请求。帐中问疾、七星坛上、华容相逢的当前图均需沿 `edits[]` 查看。其余九图使用初版请求。
2. **事后可编辑配方**：[v0.2 重建配方](rebuild-v0.2.0.json) 是生成之后整理的原文依据、表演与场景方案，不是当时提交给图片工具的完整 prompt。它不能反证旧图已满足其中每项规则。
3. **通用模板**：[提示词工作流](../../prompts/README.md) 可用于后续新作，不证明现存图片使用过该模板。

[12 图结构化追溯](maker-trace-v1.json) 逐项记录：原文 marker 与字节引文、事后解释及其出处、初版／编辑请求指针与字符串哈希、参考图角色和可核对哈希、原始／当前生成文件标识、公开素材 ID／实际结果哈希、助手检查与创作者状态。哈希仅证明所绑定的字节相同，不证明美术正确。

- `fleet-v1` 在原始请求里只供水墨风格，不是锁定舰队几何、船型或旗色的跨机位母版。人物图供身份，不保证场景连续。
- 三张 v2 都保留初版指针及生成标识。固定公开输入只含当前图，不含这三张 v1 的 PNG 字节，所以初版图哈希为 `null / not_in_public_input`，不能拿 v2 哈希代替。源仓库内历史 PNG 若另行恢复，须独立核验才可补录。
- 七星坛修订的 `edits[0]` 只明确旧图对象与修订 prompt，没有独立 `file`、日期或完整 `refs`。当前输出关联来自父层 `file` 与 `generation-files.json`，缺失字段按缺失记录，不猜测额外人物参考。
- 工具记为 Codex built-in image_gen；具体模型版本与 seed 没有记录。生成文件名是结果标识，不是 seed，不能承诺逐字节重跑。
- 2026-11-12 的单图助手检查原样保留。下述补充成对检查指出一个未解决的问题；原有 `passed` 不能被解读为这次成对检查通过。创作者最终美术检查仍 `pending`。

## 已应用到当前三图的门槛

[成对记录](paired-shot-continuity-v1.json)：黄盖出船 → 曹营观船 → 火起三江，当前结论 **needs_revision**。

实际看图：黄盖出船的小船旗偏红，曹营观船中来船旗偏蓝绿，火起三江左前火船旗又偏红。原始出船／火攻 prompt 没有约束共同旗色，观船 prompt 却明确了 blue-green。原文同一来船队两处写到「青龍牙旗」。当前图之间旗色连续性不通过，不能说“旗色都符合原文”或“已经修正”。火光可能改变感知，但这不能替代出船到未燃来船之间的色相解释。

未来修图建议把同一火船队的 **蓝绿／青色旗作为共享规范状态**，并给各机位附同一旗帜色板与对应船只参考。它是有原文依据的制作选择，不是已修改的输出，也不把“青”当成经过考古确定的精确 RGB。牙旗形制、旗上文字不在本次修复范围内自动补造。历史禁止旗上文字的 prompt 保留；今后若要恢复字样，应另提范围并检查。

正常变化不算穿帮：日暮出船到月下接近有时间推进；未燃→点燃→蔓延岸营有原文事件依据。黄盖火船甲板、曹操大船甲板、前景无名小舟是不同物件，不要求栏杆一致；黄盖、曹操和无名舟子也不能互相认作同一人。火攻全景的暖天边与月下观船存在光色观感差异，列为警告，不能用新图倒改原文时序。山形和航向只作文学示意，不冒充精确地理。

## 后续每一组只做这六步

1. 选 2–3 张相邻叙事图，锁定资产 ID／哈希及原文瞬间，不先写“通过”。
2. 填 [轻量工作表](../../prompts/paired-shot-continuity-worksheet.json)：同一物件、人物所知、船位／可见性、旗帜、光照／风、动作前后。
3. 分出“必须一致”“有事件依据可变”“不同物件”“看不清”。先定共享世界状态，再派生机位；不要用反打或画外解释所有差异。
4. 两图并看，以实际像素填观察及问题，不以 prompt 愿望代替结果。无图则 `not_checked`。
5. 任一无依据变化为 `needs_revision`；可接受艺术压缩为 `warning` 并写明代价。没有未知项或失败项才可提出 `passed`，且这不是创作者最终批准。
6. 若做修复，新增 edit 记录、实际参考角色、输出 ID／哈希；回看前后图，不能只重算哈希。保留初版请求与结果，重新检查后再改门槛结论。

离线校验：`python tools/chibi_provenance.py --source /path/to/taleprism-v0.1.0-chibi-reader.zip`。构建仍使用固定 v0.1 原包；追溯材料随源码和独立阅读包 `storygal-source/` 携带，制作工程 README 中也注明门槛与材料位置。此校验验证证据绑定与未擅自晋升状态，不代替看图审美。
