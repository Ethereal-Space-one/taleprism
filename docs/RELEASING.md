# Release procedure

The release version comes from `backend/pyproject.toml`; product, prompt-library and project-format versions are independent. The current application is 0.3.1 and the prompt library remains 0.2.0; editable projects retain format v2 and backward imports.

1. Freeze the planned scope, update versions and docs, regenerate prompts/schemas and run the checks in CONTRIBUTING. Build the frontend before constructing reader archives.
2. Review new files, stage the intended source, and run `python3 tools/release_files.py --refresh`. Inspect `tools/public-source.json`, then stage it. `--check` compares it with the tracked public inventory. Ordinary packaging only reads that list: local working files are not discovered by directory traversal. An extracted source archive can be repackaged without Git using the same list.
3. Build Last Light with `uv run --project backend python tools/build_release.py --output .release/v0.3.1`. For a complete release, add `--chibi-source /path/to/taleprism-v0.1.0-chibi-reader.zip`. Obtain that input from the existing v0.1.0 Release; the Chibi builder verifies its pinned hash and internal inventory. The build must not depend on downloading its own unpublished release or on private historical projects.
4. Verify editable import/re-export, unchanged source text, dependency-bound checks, silent public examples and standalone reader inventories. Inspect the actual art against the recorded source moment; assistant checks remain separate from final creator approval.
5. Run desktop/mobile browser checks under the `/taleprism/` subpath, including progress migration from the current online Chibi reader. Test installation from a curated source archive with fresh application data. Record actual results in `docs/VALIDATION-v0.3.1.md`.
6. Construct the final example archives once. `python3 tools/update_release_catalog.py .release/v0.3.1/release-manifest.json` pins project and reader artifacts by explicit example ID and kind. Preserve unrelated examples. Update the fixed `ARCHIVE_FILE`, `ARCHIVE_URL` and `ARCHIVE_SHA256` in `backend/src/storygal/guided_sample.py` to the frozen Last Light project, and run its pin/download-boundary tests; do not relax its fixed-origin validation. After committing the catalog and docs, use `uv run --project backend python tools/package_source.py --output .release/v0.3.1/taleprism-v0.3.1-source.zip`. Run `uv run --project backend python tools/finalize_release.py` to verify source and starter contents and bind the six ZIPs to that commit in the manifest and checksum file. Preserve the frozen example ZIPs through publication.
7. Push the candidate and require the actual Ubuntu/macOS workflow checks to pass. Create tag `v0.3.1` at the final passing commit. Create a draft Pre-release with the six ZIPs, unified manifest and checksums. Download the actual uploaded attachments and verify their bytes, checksums and reader inventories before publishing.
8. Publish the Pre-release, then run the **Publish reading example** workflow on `main`. The `github-pages` environment allows deployments from `main`. The workflow uses the exact committed catalog pin. Check the deployed Chibi URL, source/media hashes, all pictures and maps, desktop/mobile reading, browser console and README download links. Capture evidence for the real deployed commit.
9. Preserve old releases and tags, including v0.2.0 and all of its attachments. Before deploying, save the current Chibi deployment commit and artifact pin. If acceptance fails, redeploy that exact prior combination; the original v0.1.0 tag predates the Chibi showcase and is not itself the correct rollback target.

No publication credentials belong in files. Normal installation, tests and sample reconstruction do not invoke paid AI services. Local maintainers use their GitHub login; CI uses its scoped job token.

## Featured online example

`examples/site.json` selects `chibi`. `tools/prepare_pages.py` verifies the outer checksum and every file before extracting the pinned reader; `--example last-light` selects the tutorial and `--archive` verifies a local candidate. Use an empty output directory.

The public 0.2 Chibi project is rebuilt from the older public reader plus current direction/review records. Both its editable archive and standalone reader omit system demonstration audio. See [the reconstruction guide](../examples/chibi/README.md) for the exact input and invocation. Chibi remains the online main experience, while Last Light stays available in Git and Releases as the compact workflow tutorial.
