# Taleprism v0.2.0 发布计划与 P2 排期

记录日期：2026-11-10。v0.2.0 发布计划已确认；2026-11-12 已开始实施，按下表执行并更新验收记录。

v0.2.0 定位为公开试用版，交付可靠的制作与恢复流程，以及可下载、可编辑、可复建的赤壁主示例。线上主体验继续使用赤壁，末班灯保留为短篇制作教程。

本文的 P2 指上一轮架构审查中的第 7—16 项优化，不是早期名为 P2 的本机配音开发阶段。

## 当前基础

- 第 1—6 项可靠性修复已完成，基线提交为 `286985d`，位于 `codex/p1-reliability-fixes`。
- 该修复基线全量本地回归为 244 项通过；独立源码包为 187 项通过、3 项预期跳过，审校专项为 7 项通过。详见 [验证记录](VALIDATION-v0.1.0.md)。0.2 最终候选需要重新执行适用检查。
- 赤壁旧工程为工程格式 v1，包含 10 个阅读场景、12 幅插图、55 条呈现记录，但制作方案中的镜头与场景定义均为零。
- 现有赤壁主体验包含 8 位角色、9 张立绘和 3 阶段地图。需要补齐制作方案与检查依据，再由升级后的工程导出新版线上阅读包。
- 当前发布脚本、下载目录和多个版本标识仍指向 0.1.0；尚未开始 0.2 推送、创建标签或线上部署。

## 执行阶段与 agent 分工

以下为执行时的角色分工，具体写入文件范围在派工时固定，避免多个 agent 同时修改同一模块。

| 阶段 | 负责人 | 工作与产物 | 验收条件 | 状态 |
| --- | --- | --- | --- | --- |
| 1. 版本与发布工具 | Agent A | 统一应用版本、构建参数、文件命名、下载目录和公开文档；发布目录明确区分两个示例 | 新产物标识为 0.2.0；产品、模板、工程格式分别管理版本；历史文档与附件保留 | 本机验证通过 |
| 2. 制作流程与迁移基础 | Agent C | 完成下列发布前 P2 修复，明确参考选择、复用语义和对白定位规则 | 赤壁迁移与示例构建使用确定、可验证的输入 | 本机验证通过 |
| 3. 赤壁工程升级 | Agent B | 在独立副本补齐镜头、原文依据、人物立场与心理、参考素材、场景分组及物件状态；提供配方和依赖清单 | 12 幅插图均有对应制作记录；实际同场景连续镜头具备完整连续性检查；无关场景不强行串联 | 本机验证通过 |
| 4. 内容复核与独立验收 | Agent D 与主 agent | 逐幅核对画面与原文，检查恢复、引用失效和重新导出；执行干净安装及桌面、手机浏览器回归 | 不依赖开发者的私有路径或未发布素材；修复后的工程和阅读成品都能复验 | 本机验收通过，创作者复核待完成 |
| 5. 推送与版本发布 | 主 agent | 汇总变更、通过远端检查、冻结提交、创建标签、上传并核验附件 | 标签、最终提交、附件和校验清单一致 | 见 GitHub Actions 和发布页 |
| 6. 线上赤壁更新 | 主 agent | 切换目录到 0.2 赤壁阅读包，检查实际部署、缓存、媒体、地图和下载入口 | 线上确实使用新产物；部署后完整复验通过 | 见 Pages 部署记录 |

第 1、2 阶段可并行；赤壁资料整理可提前进行，正式迁移依赖第 2 阶段稳定。Agent D 可提前编写验收场景，最终验收覆盖合并后的结果。远端提交、版本标签、Release 和 Pages 由主 agent 统一操作。

## P2 分批安排

影响示例正确性、可复制性或公开交付的项目纳入 0.2。其余三项已知阅读交互问题进入 0.2 发布后的首个补丁版 0.2.1，不以等待用户反馈作为开工条件。

| 审查编号 | 优化项目 | 安排阶段 | 验收重点 |
| --- | --- | --- | --- |
| 7 | 仅供身份参考的图片无法充分参与生图任务 | 0.2，赤壁正式迁移前 | 身份参考与读者端展示立绘职责明确；选中的参考进入任务及检查依据；变更后正确失效 |
| 8 | 复用画面的语义与母版选择不一致 | 0.2，赤壁正式迁移前 | 明确实际复用的图片，任务与界面保持一致；不能自动把场景母版当作所有镜头的成图 |
| 12 | 配方无法区分文本相同的多处对白 | 0.2，示例重建前 | 使用原文位置等确定性依据定位；重复对白不串人、不依赖模糊匹配 |
| 14 | 通用功能依赖本机赤壁样例文件 | 0.2，示例重建与干净安装前 | 缺少可选赤壁素材时，普通小说的制作、恢复与导出仍正常；公开赤壁示例依赖可获得 |
| 13 | 源码打包可能混入未跟踪文件 | 0.2，发布附件构建前 | 发布输入采用明确允许范围；临时文件、运行数据与凭据不会因目录遍历进入公开源码包 |
| 15 | 启动器不能充分识别正在运行的工作区 | 0.2，安装验收前 | 同端口的其他工作区或服务不会被误认；启动与停止只针对正确实例 |
| 16 | 通用模型接口仍显示固定服务商文案 | 0.2，公开文档与界面冻结前 | 显示配置对应的服务与能力；按钮、错误提示和文档一致；不暴露密钥 |
| 9 | 连续滚动与对白播放的衔接 | 0.2.1，发布后的首个补丁批次 | 滚动、主动跳转、查阅返回分别有明确播放行为；不重复播放、不错误停止或串播 |
| 10 | 插图内部书签与返回位置不完整 | 0.2.1，同一阅读交互批次 | 保存图片标识和图内位置；刷新、重排、手机切换后合理恢复；旧书签可迁移 |
| 11 | 图片加载失败后的重试 | 0.2.1，同一阅读交互批次 | 可主动重试并清除失败状态；不循环请求；重试成功后正文和阅读位置稳定 |

若第 9—11 项在 0.2 赤壁验收中造成正文无法继续阅读、主阅读进度被覆盖或无可用恢复路径，则提升为 0.2 发布阻断项，修复后再发布。一般交互改善按上述补丁排期推进。

0.2.1 的三项共用阅读位置与媒体状态，应由同一实现 agent 集中处理，另由独立 agent 验证组合场景，避免滚动、音频和图片恢复规则互相冲突。

## 赤壁内容与工程要求

1. 保留原工程和原始文本；只在独立副本迁移。阅读编排、地图和已有正文锚点需要逐项核对。
2. 为每幅图补齐具体情节瞬间、参与人物、双方立场、外在神情、不可提前表现的内容以及参考职责。艺术解释与原文依据分开记录。
3. 按实际地点及连续关系定义场景。固定布局、道具位置、出入画原因和允许变化写入对应镜头。
4. 优先沿用现有画面；发现影响阅读的人物表演或连续性问题时局部修复。新增或修订图需重新检查其依赖镜头。
5. 检查记录绑定当前原文及素材，署名和说明来自实际复核。助手制作检查与最终创作者复核分别保留，不批量代填通过。
6. 赤壁可编辑工程与独立阅读包均排除本机系统演示音频。公开构建使用有版本和校验值的输入，下载者无需持有开发者本地工程才能复建。
7. 同步升级末班灯教程及工程，使示例、提示词、Schema 与 0.2 工作台规则一致。

## 发布验收与回滚

- 最终候选重新运行完整适用回归、前端构建、提示词与 Schema 同步、源码包检查和干净安装。旧工程可以恢复，未完成检查不能自动成为通过。
- 赤壁及末班灯工程都执行导入、编辑、导出、重新导入验证；原文与媒体清单通过校验。
- 浏览器验证桌面和手机布局、全部图片、地图切换、续读、独立包和无工作台接口依赖。跨版本阅读记录的兼容性也纳入验收。
- 远端 Ubuntu/macOS 检查实际通过后，冻结提交与产物，创建 `v0.2.0` 草稿 Release；附件上传后回下载核验，再发布公开试用版。
- Pages 使用已固定校验值的 0.2 赤壁阅读包，上线后再次核对真实 URL、媒体和下载入口。
- 发布前记录当前赤壁部署对应的提交及附件校验值。若新版线上验收失败，恢复该组合；不能仅按旧标签名推定它就是当前赤壁版本。
