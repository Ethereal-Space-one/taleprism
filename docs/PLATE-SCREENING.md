# 逐幅动静判读：看完这张画，再决定它动不动

先准备这一张**实际放进正文的图**和它出现之前读者能看到的文字。不是提示词、缩略图名或按书打的一个总勾。打开实图：挑出你确实看到的局部，抄下一处能说明**时机**的原句，说清读者此刻要看什么、哪里不能动。原句没有写浪高、雨势或具体光色时，把这些称作画面的创作解释，不补写进原作。

## 两个不同的问题：此处能出场吗？值得动吗？

当前源码的「逐幅审图」先看**出场时机**：在当前读本的实际出场位置，比较原文、实图以及给读者看的标题、说明与替代文字。先选「此处可出场」或「需要调整」，再填写展开的「原文短引」与「判断理由」并保存。再看**动静选择**：决定这张图是否值得动。不能因为雨效通过了就让尚未出场的人进入图中，也不能只凭命中一句原文判定整幅图安全。单独在试读稿中检查封面、图集、声音与播放按钮可能更早的曝光。详见[制作台步骤、签核与恢复范围](快速上手.md#这幅画能在这里出场吗)。

已发布的 v0.9.3 保留旧动静流程。下文的 JSON 与 CLI **只检查动静工作表**，无论来自示例还是另一台电脑，都不转移或自动批准出场时机。

## 在工作台怎么走

1. 选好入书的插图、放置段落，打开 **逐幅审图 → 动静选择**（旧版为 **逐幅动静审图**）。刚生成、仍未放入正文的候选，不是已经终审过的镜头。每幅实际图从「未审」开始，静态显示不构成审查结论。
2. 作一个有理由的决定。**留静：**说明为何不动更好；**动效候选：**写受影响的区域、阅读收益、保护区，选真实载体能表现的雨线/湿地或江岸回浪；**待支持：**动作值得，但现有载体表达不了，记下缺的能力，留静，不拿别的效果来代替。每次可以只审一幅，保留未完成项。
3. 决定「值得动」不启动渲染。若真的制作，仍需在动效导演绑定实际底图、圈保护范围、主动预览复核并保存章节编排。已经跑过的读本也要核对正常阅读和减少动态两种设置。审图手记、曾做过的效果和观测到的本次播放是三条不同的证据。**另看遮挡：**在同一几何下对照原图和成品多帧。被保护的人、手、道具、枝叶应不被覆盖，效果区则要真的有变化。动画开了但遮挡不合格，就同时记录两件事及待修位置，不能写成艺术已通过。
4. 在 **交付检查** 完成正式签核前，当前逐幅判读必须完整、无矛盾。未审或明明留静却仍挂着可播放方向时，要先解决；有理由的静图或明确延期也可以完成编辑判断。你仍可导出工作草稿、可编辑工程或阅读包试读。历史签核记录归于当时的作品状态，不自动当作本次签核。
5. 换图、改裁切/画布大小、换图版身份、改原文或落点时，核对当前绑定。旧意见不能凭同名图直接继承；整部原文没变时，其他身份、文件和落点均未变的图不必重写；整部原文摘要一变，全部重审。换电脑另存**私下审图工作表**，随可编辑工程携带，在同一作品/核对过的恢复副本中导入；不要把含私下审校理由的工作表放入读者 ZIP。

示例工程恢复后，仍然从「未审」开始。若作者要沿用这四部示例的公开审图结果，先打开工作台核对「实际图」，再导入对应的作者用工作表：《末班灯》用普通工作表；《赤壁》旧工程里是带 `plan-` 的 12 个独立图版 ID，用[工程恢复专用工作表](../examples/plate-screening/chibi-restored-worksheet.json)，不是改名绕过检查。只有原文、所有实际图、尺寸和落点一致、且本人明确确认是同一作品的完整副本，才能在新工程身份上采用。未公开两本现代演示的工程版本，也没有让例书自动通过。

实图、原句、所见、决定、想要的局部动作或静态重心、保护区、理由，是每条记录的核心。`verification` 是作者的补充说明，不是认证票。当前入书图版集合来自读本自己的章节编排，不以「文件夹里有几个 PNG」计数，也不让封面、人物立绘或档案夹具冒充另一部故事。

## 只用命令行/已导出的小说

从项目源码安装锁定 Python 依赖；仅需做真实浏览器验证时才安装 `tools/webgal-verify` 的锁定 Node 依赖及 Chromium。下面使用自己的阅读包（不要就地改老文件）。初始化会依据已验证的原文、图像和位置列出真正的入书插图；手写意见与读本分开存放。

```sh
uv run --project backend python tools/screen_plates.py init 我的书.zip 审图.json
# 用文本编辑器填写这份私下工作表，也可用工作台的导入/导出。
uv run --project backend python tools/screen_plates.py check 我的书.zip 审图.json
# 有受支持的动效并要核对是否真正播放：
uv run --project backend python tools/screen_plates.py check 我的书.zip 审图.json --probe --chromium /path/to/chromium
# 改图或重导出后，生成另一个文件；只保留完全匹配的记录。
uv run --project backend python tools/screen_plates.py init 新读本.zip 再审.json --previous 审图.json
```

`check` 返回非零即未通过。普通检查只判断覆盖、证据、绑定和载体是否一致；没有独立播放证据，不应把候选称为已生效。`--probe` 使用可信阅读器代码、离线浏览器和实际可见画布，按正常与系统减少动态两种设置测量；不调用模型、上传作品或替读者开启浏览器声音权限。不受信的旧运行时可以做静态判读，不能让 CLI 为了验证而执行未知网页。窄屏、物理听感与 Safari 真机需要另外做，不因 Chromium 检查而自动通过。

| 最终文件和恢复出的工作必须各验一次；未采用的意见不塞进读本 | [交付程序](RELEASING.md)、[逐图 CLI](../tools/screen_plates.py)、[四读本相同构建的工作表和实测门禁](../tools/check_plate_studies.py)。工作表由作者单独保存。可证明在所测浏览器发生什么，不能代替读者感觉与权利审查。 |

English: each *placed narrative plate* needs a source-grounded editorial decision. “Unassessed”, “keep still”, “supported candidate” and “worthwhile but unsupported” are not interchangeable. A decision never turns playback on; only an independent observation of this export can establish active motion. Real frames and a human aesthetic verdict answer different questions.
